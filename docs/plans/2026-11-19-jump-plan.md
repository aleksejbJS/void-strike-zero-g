# Jump and Double Jump Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Space jumps (≈1.5 fighter heights); a second Space in the air does one double jump (≈+1 height) drawn with a 0.4 s forward flip; the jetpack stays on W.

**Architecture:** The jump lives in the shared Force Pipeline (`movement.ts` via `playerControl.ts`), so the server, the P2P host and client prediction run it identically. The simulation keeps three plain entity fields (jump key held last tick, air jump used + its direction, rising from a jump); the flip is purely cosmetic — each client's fighter animator starts a 0.4 s rotation when it sees the air-jump field turn on.

**Tech Stack:** TypeScript, Matter.js (collision only), PixiJS 8, Vitest.

**Spec:** `docs/plans/2026-11-19-jump-spec.md`

5. **Landing mid-flip** (low ceiling, double jump next to a ledge) → the rotation stops at upright, the fighter is not left tilted. Pinned in Task 4.

Rules for `applyJump`, called in `applyMovement` after the jetpack step and before friction:
- No jump while `p.grapple.active` or `p.wound` (one-legged).
- `p.isGrounded` → `airJump = 0` and, on `jumpPress`, `vel.y = -JUMP_SPEED`, `jumpRise = true`.
- Airborne, `jumpPress`, `airJump` not ±1 → `vel.y = -AIR_JUMP_SPEED`, `jumpRise = true`, `airJump = sign(inputX) || facing`.
- `jumpRise` ends (false) once `vel.y >= -HARD_SPEED_CAP` or on the ground.
- `upwardCap(p)` = `jumpRise ? max(JUMP_SPEED, AIR_JUMP_SPEED) : HARD_SPEED_CAP`; `movement.ts` step 6 clamps `vel.y` to `[-upwardCap(p), HARD_SPEED_CAP]`.
- A ground jump must actually leave the floor in the real Matter loop (watch the grounding band the jetpack takeoff fix dealt with: `takeoff.test.ts`).

### Task 4: The flip

**Files:**
- Create: `src/game/render/fighter/fighterFlip.ts`, `src/game/render/fighter/fighterFlip.test.ts`
- Modify: `src/game/render/fighter/fighterAnimator.ts` (per-fighter `flip`, frame field), `src/game/render/fighter/fighterView.ts` (`FighterFrame.flipAngle`, gun layer, rotation)
- Test: `src/game/render/fighter/fighterViewFlip.test.ts` (new)

**Interfaces:**
- Consumes: `Entity.airJump` (Task 1).
- Produces:
  - `FLIP_MS = 400`; `class FighterFlip { observe(airJump: number | undefined, nowMs: number): number }` — returns the rotation in radians (0 when not flipping). Starts when `airJump` goes from 0/undefined to ±1 **between two observations**; the first observation never starts one. Angle = `dir · 2π · t / FLIP_MS`, 0 once `t ≥ FLIP_MS`, 0 at once when `airJump` returns to 0 (landed). A clock stepping back gives 0.
  - `FighterFrame.flipAngle?: number` (default 0). `drawFighter` rotates the whole fighter about its body centre (feet origin, centre `STANDING_HEIGHT / 2` px above) by `flipAngle`; `weapon` and `light` move into a new child container `gunLayer` that gets the opposite rotation about the same point, so the gun stays exactly where the unrotated pose puts it (the real shot point) and keeps aiming at the cursor. Arms may leave the gun during the turn.
  - `fighterAnimator` sets `flipAngle: m.flip.observe(p.airJump, now)` next to `squash`.
