# Robot 3D Kit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Robot base is a 3/4-view puppet kit rendered from a procedural Blender model. It has a tintable
paint layer, working grip/open hands, and migrated saved colours. It is used everywhere the Robot appears.

**Architecture:** Blender scripts build the robot (`tools/blender/build_atom_robot.py`) and render every part
twice into one WebP atlas: a neutral *paint* pass and an untinted *fixed* pass. They also generate a
TypeScript data module. The game keeps its rigid-part renderer, with three shared extensions: `paintOffset`
(a second, tinted mesh under the fixed one), four hand-pose parts (palms under the weapon, gripping fingers
over it) and an `armed` flag that picks grip or open hands.

**Tech Stack:** Blender 5.2 LTS (Python, EEVEE, numpy), TypeScript 5.8, Pixi.js 8.14, Vitest 1.6, Playwright 1.57
(visual checks).

**Spec:** `docs/plans/2026-11-10-robot-3d-kit-spec.md`.

### Task 2: Kit renderer (two passes, hulls, WebP, generated data)

**Files:**
- Create: `tools/blender/render_kit.py`, which grows from the spike's `render_atom_kit.py` (split helpers
  into `tools/blender/kit_atlas.py` if it passes 200 lines).
- Create (generated): `src/game/render/characters/data/robotKit.ts` and `public/assets/characters/kit/robot.webp`.

**Interfaces:**
- Produces `ROBOT_KIT: BodyKitData`. Task 3 defines the type in `src/game/render/characters/kitTypes.ts`;
  the generator writes a matching literal:

```ts
export interface KitPartData {
    polygon: readonly XY[];      // convex hull of the part's alpha, frame px (anatomy copy)
    origin: XY; axisEnd?: XY;    // frame px
    atlas: { polygon: readonly XY[]; origin: XY; axisEnd?: XY }; // the fixed pass, atlas px
    paintOffset?: XY;            // atlas px from the fixed crop to its paint crop; absent = no paint pixels
    channel: ArtChannel;         // head torso arm leg (spec mapping); 'none' for palms and grips
    supportHeight?: number;      // feet only, rig units
}
export interface BodyKitData { frame: XY; atlas: { imagePath: string; size: XY }; hip: XY; neck: XY;
    parts: Partial<Record<ArtPartId, KitPartData>> }
```

- [ ] **Step 1:** Render each part twice with the 32° yaw camera:
  - the paint pass: only `layer == "paint"` materials visible, the others as holdout;
  - the fixed pass: paint materials made transparent.

  The crop box is the union of both passes' alpha. Hull: a monotone-chain convex hull of alpha > 0.02,
  simplified to at most 24 points, padded by 4 px.
- [ ] **Step 2:** Joints:
  - palms and grips: origin `grip<Side>`; no axis;
  - other parts: spike mapping;
  - `supportHeight` = (sole y − ankle y) × 19/600.
- [ ] **Step 3:** Shelf-pack every crop into one atlas, at most 2048 wide, and save it as WebP at quality 88.
  Write `robotKit.ts` with a header comment naming the generator and the source .blend.
- [ ] **Step 4:** Run it headless. Expected: the atlas is ≤ 400 KB and `robotKit.ts` type-checks against
  Task 3's types. If Task 3 is not merged yet, check the shape by eye against the interface above.
- [ ] **Step 5:** Commit with the message `feat(robot-kit): render the robot as a two-layer 3/4 atlas`.
