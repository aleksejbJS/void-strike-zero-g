# Настройка Supabase (аккаунты и турниры) — до релиза

Игроки регистрируются «ник + пароль». Данные хранит бесплатный сервис Supabase. Пока вы не выполните
шаги ниже, игра работает как раньше (только гостем), кнопок аккаунта в ней не видно. Ничего платного.

Что понадобится: аккаунт на supabase.com (можно войти через GitHub) и права владельца репозитория на GitHub.

Проект уже создан и настроен (части 1–5). Для релиза 0.4.25 нужен только раздел **«Турниры»** в конце этого файла.

## Часть 1. Создать проект в Supabase

1. Откройте supabase.com, нажмите **New project**.
2. Название — любое (например, `void-strike`). Придумайте пароль базы данных и сохраните его в менеджере
   паролей (игре он не нужен). Регион — ближайший к игрокам (например, Frankfurt). План — **Free**.
3. Нажмите **Create new project** и подождите 1–2 минуты, пока проект создастся.

## Часть 2. Выключить подтверждение почты

У игроков нет настоящей почты (мы подставляем служебный адрес из ника), поэтому подтверждение нужно выключить.

4. В левом меню откройте **Authentication** → **Sign In / Providers** (в старом интерфейсе — **Providers**) → **Email**.
5. Выключите переключатель **Confirm email** и нажмите **Save**.

## Часть 3. Создать таблицы

6. В левом меню откройте **SQL Editor** → **New query**.
7. Откройте в репозитории файл `supabase/migrations/20261103000000_accounts.sql`, скопируйте **весь** текст
   и вставьте в окно запроса.
8. Нажмите **Run**. Должно появиться `Success. No rows returned`. Запускать повторно безопасно.

## Часть 4. Скопировать адрес и ключ

9. Откройте **Project Settings** → **API** (в новом интерфейсе — страницы **Data API** и **API Keys**).
10. Скопируйте **Project URL** (выглядит как `https://xxxx.supabase.co`).
11. Скопируйте ключ **anon public** (длинный, начинается с `eyJ`). Подойдёт и **Publishable key**
    (начинается с `sb_publishable_`). Ключ публичный по задумке: данные защищены правилами базы (RLS).
    Ключ **service_role** / **secret** копировать нельзя — он даёт полный доступ.

## Часть 5. Передать их сборке на GitHub

12. В репозитории на GitHub: **Settings** → **Secrets and variables** → **Actions** → вкладка **Variables**
    (не Secrets!) → **New repository variable**.
13. Создайте две переменные, имена — точно как написано:
    - `SUPABASE_URL` — значение из шага 10;
    - `SUPABASE_ANON_KEY` — значение из шага 11.
14. Релиз (слияние в `main`) соберёт игру уже с аккаунтами. Чтобы пересобрать без слияния:
    **Actions** → **Deploy to GitHub Pages** → **Run workflow**.

## Часть 6. Проверить

15. **Actions** → **Supabase keep-alive** → **Run workflow**. Через минуту запуск должен стать зелёным,
    **и в нём не должно быть жёлтого ⚠️ предупреждения** (оно значит, что переменные из шага 13 не заданы,
    и проверка на самом деле ничего не сделала).
    (Этот запуск раз в 3 дня будит бесплатный проект: без него Supabase усыпляет проект через 7 дней без запросов.)
16. Откройте опубликованную игру (после шага 14) и на экране выбора бойца создайте два тестовых аккаунта:
    один с латинским ником (например, `Alex`) и один с кириллическим (например, «Тест»). Пароль — не короче 6 символов.
    Для каждого: выйдите и войдите снова. В Supabase в **Table Editor** → `profiles` появятся две строки с этими никами.
    Если регистрация не проходит, игра покажет только общее сообщение «Сейчас нет связи с аккаунтами. Повторите
    чуть позже.» — настоящая причина видна в консоли браузера (**F12** → вкладка **Console**). Если там есть текст
    **«Email address is invalid»**, остановитесь и скажите разработчику: Supabase не принимает служебный адрес
    игроков, и домен адреса нужно менять в коде **до того, как появится хоть один
    настоящий аккаунт** (потом уже нельзя: аккаунты привязаны к этому адресу).

## Локальная разработка

17. Скопируйте `.env.example` в `.env.local` (этот файл не попадает в git), впишите те же два значения и
    перезапустите `npm run dev`. Пустые значения — игра запустится без аккаунтов.

## Если что-то не так

- **Регистрация пишет «ошибка сети»**: откройте консоль браузера (F12) — там указана причина. Чаще всего это
  включённое **Confirm email** (шаг 5) или не выполненная миграция (шаг 8).
- **Миграция (шаг 8) остановилась с ошибкой про «Database locale»**: база не умеет переводить кириллицу в нижний
  регистр, и проверка ников отвергала бы русские имена. Ничего не создано. Покажите текст ошибки разработчику.
- **Вход и проверка ника не работают, хотя игра открывается**: проект мог уснуть. В Supabase нажмите **Restore project**;
  проверьте, что последние запуски **Supabase keep-alive** зелёные.
- **Keep-alive перестал запускаться**: GitHub отключает расписание, если в публичном репозитории 60 дней нет
  активности. Во вкладке **Actions** включите workflow заново.
- **Забытый пароль игрока восстановить нельзя** — так задумано (нет почты). Это же предупреждение игрок видит при регистрации.

## Турниры (релиз 0.4.25) — выполнить ДО слияния в main

Турниры хранятся в той же базе Supabase, новых проектов и переменных не нужно. Но на сайте переменные
`SUPABASE_URL` и `SUPABASE_ANON_KEY` уже заданы, поэтому кнопка **«Турниры»** появится в игре сразу после
выхода релиза. Если база к этому моменту не подготовлена, кнопка будет, а турнир создать не получится.
Поэтому порядок такой: **сначала шаги 1–6, и только потом слияние pull request** (слияние и есть релиз).

1. Откройте проект в supabase.com → в левом меню **SQL Editor** → **New query**.
2. Откройте в репозитории файл `supabase/migrations/20261104000000_tournaments.sql`, скопируйте **весь** текст
   и вставьте в окно запроса.
3. Нажмите **Run**. Должно появиться `Success. No rows returned`. Запускать повторно безопасно: ничего не
   сломается и данные не пропадут.
4. Откройте **Table Editor**. В списке должны появиться три таблицы: `tournaments`, `tournament_seats`,
   `tournament_matches`.
5. Откройте **Database** → **Publications** → строка **supabase_realtime** (нажмите на число таблиц в ней).
   Переключатель **должен быть включён ровно у двух таблиц: `tournaments` и `tournament_matches`**
   (миграция включает их сама, вам нужно только проверить). Остальные таблицы вашего проекта здесь могут быть
   или не быть, это не важно.
6. **Не включайте `tournament_seats`.** В ней лежат секреты мест игроков (по ним сервер понимает, что запись
   делает именно этот игрок), и через Realtime они не должны уходить в браузеры. Если эта таблица оказалась
   включённой, выключите её.

Дальше можно сливать pull request. Если Realtime у проекта недоступен или выключен, игра не ломается: список
и сетка начнут обновляться опросом раз в 5 секунд.

**Плакаты на арене «Яма» (по желанию).** В `#ads-admin` появились два новых места, `pit.wall-poster-a` и
`pit.wall-poster-b` (300×250). Пока коды не добавлены, на стенах висят обычные плакаты игры.

### После релиза проверьте вручную

Нужны два браузера (или обычное окно и окно инкогнито; для проверки зрителей — ещё несколько).

- Создайте турнир (**Турниры** → **+ Создать турнир**): он появился в списке.
- Во втором браузере зайдите по ссылке из лобби (**Copy link**) и запишитесь. В первом нажмите **Старт**.
- Сыграйте дуэль до 10 убийств: после матча вы возвращаетесь к сетке, победитель идёт дальше.
- Закройте вкладку одного бойца посреди матча: второй боец проходит дальше примерно через минуту.
- Откройте два идущих матча сразу (выбывшим бойцом или из списка кнопкой **Смотреть**): они делятся
  на разделённом экране. Разверните плитку кликом: на стенах «Ямы» видны плакаты.
- Частота у бойцов остаётся около 120 тиков в секунду, пока матч смотрят 4 зрителя (в матче нажмите **F3**
  и смотрите строку «physics …/s»: у бойца она должна быть около 120).
- Замер для разработчика: исходящий трафик браузера-хозяина при 6 зрителях пока не измерен. Если у бойца при
  этом падает частота, в коде уменьшают `SPECTATOR_CAP` (сейчас 6).
- После финала на экране сетки появляется окно «Achievement unlocked»: Champion у победителя, Finalist у
  второго финалиста, Flawless у того, кто выиграл матч 10:0 (повторно одно достижение не выдаётся).

### Если что-то не так (турниры)

- **Кнопка «Турниры» есть, но создать турнир нельзя**: миграция (шаг 3) не выполнена или остановилась с
  ошибкой. Выполните её ещё раз и пришлите текст ошибки разработчику.
- **Лобби или сетка обновляются с задержкой в несколько секунд**: Realtime выключен (шаг 5), игра работает
  через опрос. Это нормально, но включите две таблицы из шага 5.
- **Старые турниры**: непринятый (не начатый) турнир пропадает из списка через 30 минут, завершённый — через
  10. Строки в самой базе удаляются сами, когда кто-нибудь создаёт новый турнир (старше 24 часов).
